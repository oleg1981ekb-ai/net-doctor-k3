# Ship: Commit, Push, PR & Merge

Выполни полный цикл публикации текущих изменений в репозитории:

0. **Справка (`-h` / `--help`)**: выведи краткую шпаргалку по шагам `/ship` и флагам (`-a` / `--auto` для автомерджа без паузы) и остановись.
1. **Проверка ветки и статуса**: убедись, что текущая ветка (`git branch --show-current`) не `main`. Запусти `git status` и `git diff`. Проверь, что нет секретов, ключей API, `.env` или локального мусора.
2. **Проверка качества (Quality Gate)**: выполни обязательные проверки и требуй exit code 0:
   - `ruff check .`
   - `pytest` (если есть тесты в `tests/`)
   - `make ai-smoke` (проверка AI-инфраструктуры по регламенту)
   Если любая проверка упала — остановись и исправь ошибки перед коммитом.
3. **Коммит**: составь сообщение в формате Conventional Commits (`feat:`, `fix:`, `refactor:`, `docs:`, `chore:`) на английском языке и закоммить изменения.
4. **Пуш**: отправь ветку командой `git push -u origin HEAD`.
5. **Pull Request**: создай PR через `gh pr create` со структурой: Что сделано, Зачем и Как проверить (приложи лог `make ai-smoke`).
6. **Подтверждение перед мерджем**:
   - Если указан флаг `-a` или `--auto` — сразу переходи к шагу 7.
   - Иначе — покажи ссылку на PR и спроси подтверждение перед слиянием.
7. **Мердж**: выполни `gh pr merge --squash --delete-branch`, переключись на `main` (`git checkout main`) и подтяни изменения (`git pull`).
